## 1. VHDL 입문자를 위한 핵심 기초 문법 완벽 가이드 (필독!)

C언어나 Python 같은 일반 프로그래밍 언어는 CPU가 **위에서 아래로 한 줄씩 순서대로(순차 실행)** 읽으며 실행합니다. 반면, **VHDL(VHSIC Hardware Description Language)**은 소프트웨어가 아니라 **실제 디지털 전자회로(전선, 논리 게이트, 멀티플렉서, 플립플롭)를 글자로 설계하는 하드웨어 기술 언어**입니다. 코드를 읽기 전에 아래 7가지 핵심 문법 규칙을 먼저 이해하면 모든 코드가 한눈에 읽힙니다!

---

### 1.1 기본 골격: `library` / `entity` (칩의 껍데기) / `architecture` (칩의 내부 회로)
모든 VHDL 파일은 크게 3부분으로 나뉩니다.

1. **`library` 와 `use` (도구함 불러오기)**:
   - C언어의 `#include <stdio.h>`나 Python의 `import`와 같습니다.
   - `library ieee;` : 국제전기전자공학회(IEEE) 표준 라이브러리를 쓰겠다는 선언입니다.
   - `use ieee.std_logic_1164.all;` : 디지털 신호(`'0'`, `'1'`, `'Z'` 등)를 정의한 필수 패키지의 모든 것(`.all`)을 가져옵니다.
   - `use ieee.numeric_std.all;` : 이진수 덧셈, 뺄셈, 크기 비교, 정수 변환(`unsigned`, `signed`, `to_integer`, `to_unsigned` 등)을 해주는 표준 수학 패키지를 가져옵니다.

2. **`entity` (블랙박스 칩의 외부 핀 정의)**:
   - 칩 밖으로 나와 있는 **입출력 다리(Port, 핀)**가 무엇인지 정의합니다. 내부 동작은 적지 않습니다.
   ```vhdl
   entity 모듈이름 is
       port (
           신호이름1 : in  자료형;  -- in  : 외부에서 칩 안으로 들어오는 입력 핀
           신호이름2 : out 자료형   -- out : 칩 안에서 외부로 나가는 출력 핀 (마지막 줄엔 세미콜론 ';' 없음!)
       );
   end entity 모듈이름;
   ```
   > **[문법 주의사항]** `port ( ... );` 안의 가장 마지막 줄 뒤에는 세미콜론(`;`)을 찍으면 문법 에러가 납니다! 닫는 괄호 `);` 바깥에만 세미콜론을 찍습니다.

3. **`architecture` (칩 내부의 실제 회로 설계도)**:
   - `entity`에서 정의한 입출력 핀들을 내부에서 어떻게 연결하고 계산할지 설계합니다.
   ```vhdl
   architecture 설계방식이름 of 모듈이름 is
       -- [선언부] 칩 내부에서만 쓸 함수(function), 전선(signal), 상수(constant) 등을 선언하는 곳
   begin
       -- [본문] 실제 회로 동작(논리식, process, 멀티플렉서 등)을 작성하는 곳
   end architecture 설계방식이름;
   ```

### 1.2 VHDL의 5대 핵심 자료형 (Data Types)과 따옴표 규칙

VHDL은 타입(자료형) 검사가 매우 엄격한 언어입니다.

| 자료형 이름 | 의미 및 하드웨어 구조 | 값 표기법 (따옴표 규칙) | 주요 용도 |
| :--- | :--- | :--- | :--- |
| **`std_logic`** | **전선 1가닥 (1비트)**<br/>(`'0'`, `'1'`, `'Z'`(끊어짐/High-Z), `'X'`(충돌) 등 9가지 전기 상태 표현) | **작은따옴표 `' '`**<br/>예: `'0'`, `'1'` | 1비트 클럭(`CLOCK_50`), 단일 스위치(`SW(0)`) |
| **`std_logic_vector`** | **전선 여러 가닥을 묶은 버스(Bus)**<br/>(단순 비트 묶음이라 **그 자체로는 `+`, `-` 산술 연산 불가!**) | **큰따옴표 `" "`**<br/>예: `"1010"`, `"1111111"` | 여러 비트 입출력 핀(`SW`, `KEY`, `HEX0~7`, `LEDR`) |
| **`unsigned`** | **부호 없는 이진수 배열 (0과 양수 전용)**<br/>(`std_logic_vector`와 똑같이 전선 묶음이지만 **`+ 1` 등 산술 연산 가능!**) | **큰따옴표 `" "`** | 클럭 카운터(`blink_cnt`), 스위치 이진값을 숫자로 바꿀 때 |
| **`integer`** | **정수 (음수, 0, 양수)**<br/>(`range -999 to 9999`처럼 범위를 지정해 합성 비트 수를 맞춤) | **따옴표 없이 숫자만**<br/>예: `0`, `777`, `-15` | 카운터 값(`count_val`), 사칙연산(`+`, `-`, `*`, `/`, `mod`) |
| **`boolean`** | **참/거짓 논리형** | **`true` 또는 `false`** | 조건 판단 플래그(`is_neg`, `div_zero`) |

#### 왜 `(6 downto 0)` 처럼 `downto`를 쓸까? (`downto` vs `to`)
- **`std_logic_vector(6 downto 0)`**: 6번 비트(가장 왼쪽, 최상위 비트 MSB)부터 0번 비트(가장 오른쪽, 최하위 비트 LSB)까지 총 **7가닥의 전선**이라는 뜻입니다.
  - 우리가 숫자를 쓸 때 왼쪽에 큰 자리(천의 자리), 오른쪽에 작은 자리(일의 자리)를 쓰는 것처럼, 디지털 회로에서도 왼쪽 비트가 $2^6$, 오른쪽 비트가 $2^0$이 되도록 **`(큰번호 downto 작은번호)`**로 선언합니다.
- **`range 0 to 9999`**: 반대로 정수 범위를 지정할 때는 작은 수부터 큰 수까지 **`(작은수 to 큰수)`**를 사용합니다.

### 1.3 자료형 변환(Type Conversion) 3단계 공식 완벽 이해

앞서 `std_logic_vector`는 단순한 전선 다발이라 산술 계산이나 정수 변환을 바로 할 수 없다고 했습니다. 그래서 `std_logic_vector` ↔ `integer` 사이에 변환할 때는 반드시 징검다리인 **`unsigned`**를 거쳐야 합니다 (`use ieee.numeric_std.all;` 패키지 함수 사용).

```text
  [전선 다발]                        [이진수 숫자]                         [10진 정수]
std_logic_vector  ──────►          unsigned          ──────►           integer
  "1000" (SW입력)   unsigned(...)    "1000" (이진수 8)   to_integer(...)      8

std_logic_vector  ◄──────          unsigned          ◄──────           integer
  "00001000"     std_logic_vector()  "00001000"      to_unsigned(값, 비트수)  8
```

1. **스위치 입력(`std_logic_vector`)을 계산 가능한 정수(`integer`)로 바꿀 때**:
   - 코드: `num_a := to_integer(unsigned(SW(17 downto 14)));`
   - 해석: ① `unsigned(SW(17 downto 14))`로 4가닥 전선 다발을 "부호 없는 이진수"로 해석한 뒤 → ② `to_integer(...)`를 씌워 정수(`0`~`15`)로 변환합니다.
2. **계산된 정수(`integer`)를 LED 출력 핀(`std_logic_vector`)으로 내보낼 때**:
   - 코드: `calc_LEDR(7 downto 0) <= std_logic_vector(to_unsigned(abs_val, 8));`
   - 해석: ① `to_unsigned(abs_val, 8)`로 정수 `abs_val`을 **8비트 길이**의 부호 없는 이진수로 바꾼 뒤 → ② `std_logic_vector(...)`를 씌워 LED 내부 신호 전선 다발에 연결합니다.

### 1.4 3가지 화살표 기호 (`<=`, `:=`, `=>`) 완벽 구별법

VHDL을 처음 배울 때 가장 헷갈리는 세 가지 기호입니다.

| 기호 | 명칭 | 언제 사용하는가? | 코드 예시 및 직관적 해석 |
| :---: | :--- | :--- | :--- |
| **`<=`** | **신호(Signal) 대입 연산자** | 실제 전선(`signal`)이나 출력 포트(`out`)에 값을 흘려보낼 때 사용<br/>*(주의: "작거나 같다"는 뜻일 때는 조건식 안에서만 쓰임)* | `cnt_HEX0 <= seg7(0);`<br/>→ "`seg7(0)`의 결과를 `cnt_HEX0` 전선에 연결하라!" |
| **`:=`** | **변수(Variable) 대입 및 초기값 연산자** | ① `process` 안의 임시 계산용 변수(`variable`)에 값을 즉시 넣을 때<br/>② 선언부에서 처음 시작할 때의 초기값(Default)을 줄 때 | `mult := 5;`<br/>→ "변수 `mult`에 지금 즉시 `5`를 넣어라!"<br/>`signal count_val : integer := 0;`<br/>→ "시작할 때 초기값을 `0`으로 해라!" |
| **`=>`** | **연결(매핑) 연산자** | ① `case`문에서 "이 조건일 때는 이것을 실행하라"<br/>② `(others => '0')`에서 "나머지 비트를 모두 `'0'`으로 채워라" | `when "00" => calc_result := num_a + num_b;`<br/>`cnt_LEDR <= (others => '0');` |

---

### 1.5 `Signal`(신호) vs `Variable`(변수) — 왜 둘 다 쓸까?

- **`signal` (신호 = 실제 하드웨어 전선 또는 플립플롭 레지스터)**:
  - `architecture` 선언부에 만들며, **`<=`**로 값을 넣습니다.
  - **가장 중요한 특징**: `process` 안에서 `signal`에 `<=`로 값을 넣으면, **그 줄에서 즉시 값이 바뀌지 않고 `process`가 끝나는 순간(또는 클럭 상승 에지가 끝나는 순간)에 예약된 값들이 한꺼번에 갱신됩니다!**
- **`variable` (변수 = `process` 안에서만 쓰는 임시 계산 메모장)**:
  - `process` 내부 선언부에서만 선언하며, **`:=`**로 값을 넣습니다.
  - C언어 변수처럼 **그 줄이 실행되는 즉시 값이 바뀝니다!**
  - 예: `num_a := to_integer(unsigned(SW(17 downto 14)));`로 스위치 값을 `num_a`에 넣자마자 바로 다음 줄 `if num_a > 9 then num_a := 9;`에서 방금 넣은 `num_a` 값을 즉시 검사하고 수정할 수 있는 이유가 바로 `variable`이기 때문입니다.

---

### 1.6 동시 실행문(Concurrent) vs 순차 실행문(`process`)

1. **`process` 바깥(`architecture` 본문) = 모든 줄이 동시에 작동!**:
   - `process` 바깥에 적힌 코드들(예: 65번 줄 `counter_enable <= not SW(0);`, 203~212번 줄 출력 멀티플렉서) 및 3개의 `process` 블록 자체는 전선으로 납땜해 놓은 독립된 하드웨어 블록들입니다. 줄의 위아래 순서와 상관없이 **전기가 통하는 내내 모든 블록이 24시간 동시에 작동**합니다.
2. **`process(감지목록)` 안쪽 = C언어처럼 위에서 아래로 순서대로 해석!**:
   - 복잡한 조건문(`if-elsif-else`, `case-when`)을 쓰려면 반드시 `process(...)` 블록을 열어야 합니다.
   - 괄호 안의 신호(**감지 목록, Sensitivity List**) 중 하나라도 값이 변하면 `process`가 깨어나서 `begin`부터 `end process;`까지 위에서 아래로 코드를 실행하여 출력 신호 값을 결정합니다.
   - 만약 같은 `process` 안에서 동일한 신호(`cnt_HEX1` 등)에 위에서 `cnt_HEX1 <= seg7(16);`을 넣고 아래쪽 `if`문에서 `cnt_HEX1 <= seg7(5);`를 또 넣으면, **가장 마지막에 실행된 값(`seg7(5)`)이 최종적으로 전선에 나갑니다.**

### 1.7 매우 자주 쓰이는 편리한 문법: `(others => '0')` 와 연산자(`mod`, `/`, `abs`)

1. **`(others => '0')` (나머지 비트 일괄 채우기)**:
   - 18비트짜리 `LEDR`을 모두 끄려고 `"000000000000000000"`이라고 0을 18개나 세면서 적으면 오타가 나기 쉽습니다.
   - 이때 `(others => '0')`라고 쓰면 비트 수가 몇 비트이든 상관없이 **"모든 비트를 `'0'`으로 채워라"**라는 뜻이 됩니다.
2. **나눗셈 몫(`/`)과 나머지(`mod`) 및 절댓값(`abs`)**:
   - 정수(`integer`)끼리 `/` 연산을 하면 소수점 아래를 버린 **몫(Quotient)**이 나옵니다 (예: `7 / 2` = `3`).
   - `mod` 연산을 하면 나눈 뒤의 **나머지(Remainder)**가 나옵니다 (예: `7 mod 2` = `1`).
   - `abs(x)`는 `x`가 음수일 때 부호를 뗀 **절댓값(Absolute value)**을 돌려줍니다 (예: `abs(-15)` = `15`).

## 4. 파트 1 (Lines 1~65): 엔티티 선언, `seg7()` 디코더 함수, 내부 신호 선언 해설

### 4.1 7-Segment 디스플레이의 하드웨어 구조와 Active-Low 원리
FPGA 보드의 7-Segment는 7개의 막대 LED(`a`~`g`)로 이루어져 있으며, **`'0'`을 주면 불이 켜지고 `'1'`을 주면 불이 꺼지는 Active-Low (Common Anode)** 방식입니다.

```text
       aaa          비트 인덱스 매핑: std_logic_vector(6 downto 0)
      f   b         bit 6 = g (중앙 가로)    bit 2 = c (우측 하단 세로)
      f   b         bit 5 = f (좌측 상단)    bit 1 = b (우측 상단 세로)
       ggg          bit 4 = e (좌측 하단)    bit 0 = a (상단 가로)
      e   c         bit 3 = d (하단 가로)
      e   c
       ddd          ==> "g f e d c b a" 순서로 7비트 문자열을 구성함 ('0'=ON, '1'=OFF)
```
예를 들어 숫자 **`0`**을 표시하려면 가운데 가로줄인 `g`(bit 6)만 끄고(`'1'`) 나머지 `f, e, d, c, b, a`(bit 5~0)를 모두 켜야(`'0'`) 하므로 **`"1000000"`**이 됩니다.

### 4.2 파트 1 코드 및 줄별 문법 해설 (Lines 1~65)

```vhdl
  1: library ieee;
  2: use ieee.std_logic_1164.all;
  3: use ieee.numeric_std.all;
  4: 
  5: -- Top-Level Entity: Counter + One-Digit Calculator (Single-File Unified Version)
  6: entity project1_top_countercalculator is
  7:     port (
  8:         CLOCK_50 : in  std_logic;
  9:         SW       : in  std_logic_vector(17 downto 0);
 10:         KEY      : in  std_logic_vector(3 downto 0);
 11:         HEX0, HEX1, HEX2, HEX3, HEX4, HEX5, HEX6, HEX7 : out std_logic_vector(6 downto 0);
 12:         LEDR     : out std_logic_vector(17 downto 0);
 13:         LEDG     : out std_logic_vector(7 downto 0)
 14:     );
 15: end entity project1_top_countercalculator;
 16: 
 17: architecture behavioral of project1_top_countercalculator is
 18: 
 19:     -- Common 7-Segment Decoder Function (Active-Low: '0' = ON, '1' = OFF)
 20:     function seg7(val : integer) return std_logic_vector is
 21:     begin
 22:         case val is
 23:             when 0      => return "1000000"; -- 0
 24:             when 1      => return "1111001"; -- 1
 25:             when 2      => return "0100100"; -- 2
 26:             when 3      => return "0110000"; -- 3
 27:             when 4      => return "0011001"; -- 4
 28:             when 5      => return "0010010"; -- 5
 29:             when 6      => return "0000010"; -- 6
 30:             when 7      => return "1111000"; -- 7
 31:             when 8      => return "0000000"; -- 8
 32:             when 9      => return "0010000"; -- 9
 33:             when 10     => return "0001000"; -- A
 34:             when 11     => return "0000011"; -- b
 35:             when 12     => return "1000110"; -- C
 36:             when 13     => return "0100001"; -- d
 37:             when 14     => return "0000110"; -- E
 38:             when 15     => return "0001110"; -- F
 39:             when 16     => return "1111111"; -- Blank
 40:             when 17     => return "0111111"; -- '-'
 41:             when 18     => return "0000110"; -- 'E'
 42:             when 19     => return "0101111"; -- 'r'
 43:             when 20     => return "1100001"; -- 'J'
 44:             when 21     => return "0001100"; -- 'P'
 45:             when others => return "1111111"; -- Default: Blank
 46:         end case;
 47:     end function;
 48: 
 49:     -- Counter Unit Internal Signals
 50:     signal count_val            : integer range -999 to 9999 := 0;
 51:     signal key_sync0, key_sync1 : std_logic_vector(3 downto 0) := (others => '1');
 52:     signal blink_cnt            : unsigned(24 downto 0) := (others => '0');
 53:     signal counter_enable       : std_logic;
 54: 
 55:     -- Output Multiplexer Signals
 56:     signal cnt_HEX0,  cnt_HEX1,  cnt_HEX2,  cnt_HEX3  : std_logic_vector(6 downto 0);
 57:     signal cnt_HEX4,  cnt_HEX5,  cnt_HEX6,  cnt_HEX7  : std_logic_vector(6 downto 0);
 58:     signal calc_HEX0, calc_HEX1, calc_HEX2, calc_HEX3 : std_logic_vector(6 downto 0);
 59:     signal calc_HEX4, calc_HEX5, calc_HEX6, calc_HEX7 : std_logic_vector(6 downto 0);
 60:     signal cnt_LEDR,  calc_LEDR                       : std_logic_vector(17 downto 0);
 61:     signal cnt_LEDG,  calc_LEDG                       : std_logic_vector(7 downto 0);
 62: 
 63: begin
 64: 
 65:     counter_enable <= not SW(0);
```

#### [줄별 문법 완전 해부 (Lines 1~65)]
- **Lines 1~3 (`library` 및 `use`)**:
  - `ieee.std_logic_1164.all`: `std_logic`, `std_logic_vector` 논리 자료형 사용.
  - `ieee.numeric_std.all`: `unsigned` 덧셈(`+ 1`)과 `to_integer()`, `to_unsigned()` 형변환 함수 사용.
- **Lines 6~15 (`entity project1_top_countercalculator is ... end entity;`)**:
  - DE2 보드의 물리 핀(`CLOCK_50`, `SW(17:0)`, `KEY(3:0)`, `HEX0~7`, `LEDR(17:0)`, `LEDG(7:0)`)과 1:1로 대응되는 최상위 입출력 포트 정의입니다.
  - **Line 11**: 같은 `out std_logic_vector(6 downto 0)` 타입인 8개의 7-Segment 포트를 한 줄로 깔끔하게 묶어 선언했습니다.
- **Lines 20~47 (`function seg7(val : integer) return std_logic_vector`)**:
  - 아키텍처 선언부에 정의된 공용 함수로, 카운터 표시 프로세스(Process 2)와 계산기 프로세스(Process 3) 양쪽에서 모두 호출합니다.
  - `0~9`는 10진 숫자, `10~15`는 16진 문자(`A, b, C, d, E, F`), `16`은 전체 소등(Blank, `"1111111"`), `17`은 음수 부호(`'-'`), `18~19`는 에러/나머지 표시용 `'E'`, `'r'`, `20~21`은 777 잭팟 표시용 `'J'`, `'P'` 패턴을 반환합니다.
- **Lines 50~53 (카운터 내부 상태 신호 선언)**:
  - `count_val`: `-999`부터 `9999`까지의 카운터 현재 값을 저장하는 레지스터(초기값 `0`).
  - `key_sync0, key_sync1`: 버튼(`KEY`)의 현재 샘플과 1클럭 전 샘플을 저장해 하강 에지를 검출하는 4비트 플립플롭 2단 레지스터(Active-Low 버튼이므로 초기값 `'1'`).
  - `blink_cnt`: 777 잭팟 점멸 주기를 만드는 25비트 `unsigned` 클럭 카운터.
  - `counter_enable`: 카운터 모드 활성화 신호(`not SW(0)`).
- **Lines 56~61 (출력 멀티플렉서용 내부 배선 선언)**:
  - 카운터 프로세스의 출력(`cnt_HEX0~7`, `cnt_LEDR`, `cnt_LEDG`)과 계산기 프로세스의 출력(`calc_HEX0~7`, `calc_LEDR`, `calc_LEDG`)이 서로 충돌하지 않도록 각각 전용 내부 신호로 분리해 선언했습니다.
- **Line 65 (`counter_enable <= not SW(0);`)**:
  - `SW(0) = '0'`(카운터 모드)일 때만 `counter_enable = '1'`이 되어 카운터 버튼 입력이 동작하고, `SW(0) = '1'`(계산기 모드)일 때는 카운터 값이 그대로 보존됩니다.

  - `calc_LEDR(7 downto 0)`에 절댓값 `abs_val`(최대 `81`)을 8비트 이진수로 표시합니다.

## 8. 심화 이론: Quartus 합성기(Synthesizer)가 VHDL 코드를 실제 하드웨어 회로로 바꾸는 원리

교수님이나 조교님의 질의응답(Level of Understanding 평가)에서 자주 나오는 핵심 하드웨어 합성 원리 3가지입니다.

1. **왜 카운터 프로세스(Process 2)와 계산기 프로세스(Process 3)가 같은 `HEX0~HEX7` 핀에 직접 대입하지 않고 `cnt_*`, `calc_*` 신호를 거쳐 MUX로 합치나요?**
   - VHDL에서 서로 다른 두 개의 `process`가 동일한 출력 신호(`HEX0` 등)에 동시에 값을 대입하면 **다중 드라이버 충돌(Multiple Driver / Bus Contention)**이 발생합니다.
   - 따라서 각 프로세스의 출력을 `cnt_HEX*`, `calc_HEX*`라는 별도의 내부 신호로 받은 뒤, 마지막 **2-to-1 멀티플렉서(Lines 203~212, `when SW(0) = '0' else`)**를 통해 한 번에 한 블록의 신호만 물리 핀으로 나가도록 설계해야 합니다.
2. **`abs_val / 10`과 `abs_val mod 10`은 하드웨어로 어떻게 만들어지나요?**
   - FPGA 내부의 Cyclone II 로직 엘리먼트(LE)들이 상수 `10`, `100`, `1000`(또는 `16`)에 대한 **조합 논리 나눗셈/나머지 연산기(Combinational Divider/Modulo Array)**로 합성되어, 클럭 대기 시간 없이 값이 바뀌는 즉시 각 자릿수가 계산됩니다.
3. **Project 2와 한 보드에 합칠 때([de2_unified_top.vhd](../de2_unified_top.vhd)) Project 1에 왜 전혀 영향이 없나요?**
   - Project 1은 `SW(5 downto 4)`를 사용하지 않으므로, `de2_unified_top.vhd`에서 **`SW(4)`**를 마스터 전환 스위치로 사용합니다 (`SW(5)`는 `SW(6)`과의 오조작 방지용 완충 간격). `SW(4) = '0'`일 때는 `KEY`와 `SW`, `HEX0~7`, `LEDR/G`가 100% Project 1에 연결되고, `SW(4) = '1'`일 때는 Project 1에 들어가는 `KEY` 신호를 `"1111"`(안 눌림)로 고정하여 Project 2 게임을 플레이하는 동안에도 Project 1의 카운터 값이 그대로 유지됩니다.
