# Design Project #2: 두더지 잡기 게임 (Crypto Miner Defense) 기획 및 구현 타당성 분석

---

## 1. 프로젝트 개요

* **프로젝트명**: 두더지 잡기 게임 - 크립토 디펜스 (가제: *Digital Miner vs. Crypto Holder*)
* **장르**: 2인용 비대칭 PvP 실시간 디펜스 게임
* **개발 환경**: FPGA (DE2 보드), VHDL
* **외부 입출력 장치 (확정)**:
  * **화면 출력**: DE2 VGA 포트 ➔ `VGA to HDMI 컨버터` + `HDMI 케이블` ➔ 모니터 (`640x480 @ 60Hz`)
  * **Player 1 (사람 조작)**: `NETmate PS/2 유선 광마우스 (NM-OM01)` (DE2 PS/2 포트 직결, 마우스 커서 위치 추적 이동)
  * **Player 1 (망치 공격)**: DE2 보드 Push Button (`KEY`) 또는 마우스 좌클릭
  * **Player 2 (두더지 소환)**: `아두이노 4x4 키패드 모듈` (DE2 GPIO 핀 직결)

---

## 2. 세계관 및 스토리

미래 사회에는 암호화폐(Crypto Coin)가 실제 화폐처럼 사용된다.  
**사람(Player 1)**은 오랜 기간 열심히 코인을 채굴하여 맵 중앙에 **100개의 코인 더미**를 모아 두었다.  
한편, **두더지 군단(Player 2 - 두더지 대장)** 역시 코인을 노리고 채굴(Mining)하려 하지만, 직접 암호를 연산할 기술이 없어 사람이 모아둔 코인을 물리적으로 빼앗아 가는 방식으로 '채굴(Mining)'을 시도한다.  
사람은 중앙의 코인 더미를 두더지(Digital Miner)들로부터 지켜내야 하고, 두더지 대장은 끊임없이 두더지를 소환해 100개의 코인을 모두 털어내야 한다.

## 3. 게임 규칙 및 상세 시스템

### 3.1. 그래픽 및 맵 구조
* **아트워크**: 도트 그래픽 스타일의 배경 월드, 사람 캐릭터(망치 보유), 포켓몬 **두더류 / 몰드류** 도트 스프라이트 활용.
* **맵 레이아웃**:
  * 정사각형 형태의 맵 정중앙에 **코인 더미(초기 100코인)**가 위치한다.
  * 코인 더미를 중심으로 일정 거리의 **내부 정사각형(안전 구역 경계)**이 존재하며, 두더지는 이 정사각형 **바깥쪽 영역**에서만 소환될 수 있다.

```
+---------------------------------------+
|  [1]     [2]     [3]     [A]          |  <- 4x4 키패드 바깥 12개 구역과 매칭되는
|                                       |     외곽 소환 가능 영역
|  [4]   +-------------------+   [B]    |
|        |   소환 금지 구역   |          |
|        |                   |          |
|  [7]   |     [코인 더미]    |   [C]    |
|        |      (100개)      |          |
|        +-------------------+          |
|  [*]     [0]     [#]     [D]          |
+---------------------------------------+
```

### 3.2. 역할 및 조작 방식 (2인용 비대칭 PvP)

| 구분 | Player 1 (사람 / 수비 진영) | Player 2 (두더지 대장 / 공격 진영) |
| :--- | :--- | :--- |
| **목표** | 5라운드가 끝날 때까지 코인 더미(100개)를 1개 이상 방어 | 5라운드 이내에 코인 더미(100개)를 모두 채굴하여 0으로 만듦 |
| **이동 방식** | **PS/2 마우스** 커서 위치를 따라 8방향(또는 360도) 추적 이동 | 소환된 두더지가 중앙의 코인 더미를 향해 **8방향 자동 이동** |
| **액션 조작** | **DE2 보드 KEY 버튼** (또는 **마우스 좌클릭**)으로 망치 공격 | **아두이노 4x4 키패드**를 눌러 해당 구역에 두더지 소환 |
| **특수 규칙** | 캐릭터 주변에 **반투명 원형 사거리**가 표시되며, 사거리 내 **가장 가까운 두더지**를 타격 | 키패드 **가장자리 12개 키**로 일반 두더지 외곽 소환, **안쪽 4개 키**는 추후 특수 두더지(몰드류 등) 소환용으로 확장 |

### 3.3. 채굴 및 전투 메커니즘
* **두더지 채굴(Mining)**:
  * 소환된 두더지는 자동으로 중앙 코인 더미를 향해 이동한다.
  * 코인 더미에 일정 거리 이내로 접근하면 **1초 동안 채굴 모션**을 취하며, 모션 완료 시 **1코인씩 감소**시킨다.
* **사람의 공격(Hammer Attack)**:
  * 사람 캐릭터 주위에 투명한 원 모양의 공격 사거리가 표시된다.
  * 두더지에게 가까이 다가가 사거리 원 안에 두더지가 들어왔을 때 DE2 보드의 KEY 버튼을 누르면, 사거리 내 **가장 가까운 두더지 1마리**를 공격하여 처치한다.

### 3.4. 라운드 및 승리 조건
* **라운드 종료 조건**: **1·2라운드는 20초**, **3라운드는 30초** 동안 진행되며(또는 두더지 50마리 처치 시 조기 종료), 종료 시 다음 라운드로 넘어간다.
* **총 라운드 수**: 총 **3라운드** 진행.
* **라운드별 난이도(속도·체력·몰드류 확률) 및 소환·공격·콤보 규칙**:
  * **시작 전 10초 룰 설명 & 3초 카운트다운**: 게임 시작(리셋) 시 처음 `10초` 동안 룰 설명 화면(`10~4초`)이 표시되고, 시작 `3초` 전(`3·2·1`) 카운트다운 후 본 게임이 시작된다.
  * **허공 공격 패널티**: 사거리($R=48$) 내에 두더지가 없는데 공격하면 사람은 **0.5초(30프레임) 동안 정지**하며 콤보가 **1단계씩 하락**한다(`LV3(9+) ➔ LV2(6) ➔ LV1(3) ➔ LV0(0)`).
  * **연속 처치 콤보 강화 (`3 / 6 / 9` 콤보, 라운드 전환 시에도 유지)**:
    * **3콤보 이상 (1단계)**: 공격 데미지 **`1` ➔ `2`** 증가
    * **6콤보 이상 (2단계)**: 사람 이동 속도 **`2 px/f` ➔ `3 px/f`** 증가
    * **9콤보 이상 (3단계)**: 기본 데미지 `2`, **`4/8(50%)` 확률로 크리티컬 강타(데미지 `3`, 넉백 없음)** 발동
  * **외곽 12개 키만 소환 사용**: 4x4 키패드의 바깥 12개 키만 입력을 받으며, 중간 4개 키(`5, 6, 8, 9`)는 입력을 받지 않는다.
  * **라운드별 두더지 속도·체력·몰드류 확률**:
    * **1라운드**: 두더류 체력 `1` (속도 `0.5 px/f`), 몰드류 **`1/8` 확률** 등장 · 체력 `2` (`1.0 px/f`)
    * **2라운드**: 두더류 체력 `2` (속도 `1.0 px/f`), 몰드류 **`2/8` 확률** 등장 · 체력 `4` (`1.5 px/f`)
    * **3라운드**: 두더류 체력 `3` (속도 `1.5 px/f`), 몰드류 **`4/8` 확률** 등장 · 체력 `6` (`2.0 px/f`)
  * **필드 최대 8마리 제한**: 동시에 필드에 존재할 수 있는 두더지는 최대 8마리(`MAX_MOLES = 8`)까지 가능하다.
  * **연속 동일 위치 소환 불가**: 직전에 소환한 구역(`last_spawn_zone`)과 같은 위치에는 연속으로 소환할 수 없다.
* **코인 누적제**: 코인(**초기 50개**)은 라운드마다 초기화되지 않고 **3라운드 내내 누적(공유)**된다.
* **최종 승패 및 실제 밈코인(50 MMC) 링크 & 수령 코드 보상**:
  * **두더지(Player 2) 승리**: 3라운드가 끝나기 전에 중앙의 코인이 `0`이 되면 즉시 승리.
  * **사람(Player 1) 승리**: 3라운드가 모두 끝날 때까지 중앙의 코인이 `1`개 이상 남아있으면 승리.
  * **승자 보상 링크 및 수령 코드 모니터 출력 (QR 코드 미사용 ➔ 텍스트 직접 출력 방식)**:

## 4. FPGA (DE2 보드) 구현 가능성 및 하드웨어 설계 분석

본 기획은 **DE2 보드와 VHDL을 통해 100% 구현 가능**하며, 평가 항목인 **창의성(Creativity)**, **완성도(Quality)**, **이해도(Level of understanding)**를 모두 만족할 수 있는 구조이다. 다만 하드웨어(FPGA) 특성에 맞춘 아래의 설계 최적화 전략을 적용해야 한다.

### 4.1. 외부 모듈 하드웨어 인터페이스 (확정)

1. **VGA 모니터 출력 (`VGA to HDMI 컨버터` + `HDMI 케이블`)**
   * DE2 보드 내장 VGA DAC를 사용하여 `640x480 @ 60Hz` (픽셀 클럭 25MHz) 해상도로 아날로그 신호 출력 후, `VGA to HDMI 컨버터`를 거쳐 HDMI 모니터에 출력.
   * 중앙 정사각형 게임 맵(`480x480` 영역)과 우측 상태 UI 영역(`160x480`)으로 화면을 분할하여 구성.

2. **아두이노 4x4 키패드 모듈 (Player 2 - DE2 GPIO 직결)**
   * Row 4핀, Column 4핀(총 8핀)의 디지털 매트릭스 구조이므로 DE2 보드 `GPIO`에 직접 연결.
   * VHDL 내부에서 Column 스캔 클럭(약 1kHz)을 돌리고 Row 입력을 디바운싱(Debouncing)하여 16개 키(외곽 12개 + 내부 4개) 입력을 정확히 감지.

3. **PS/2 유선 광마우스 (`NETmate NM-OM01`, Player 1 - DE2 PS/2 포트 직결)**
   * DE2 보드 내장 PS/2 포트(`PS2_CLK`, `PS2_DAT`)에 직접 연결하여 별도의 ADC나 아두이노 없이 깔끔하게 하드웨어 구성.
   * VHDL 내부의 PS/2 양방향 컨트롤러가 초기화 시 `0xF4`(Enable Data Reporting) 명령을 전송하고, 이후 마우스로부터 3바이트 이동 패킷(`버튼 상태`, `ΔX`, `ΔY`)을 실시간 수신.
   * 화면상의 마우스 커서 `(cursor_x, cursor_y)` 좌표를 갱신하고, 사람 캐릭터 `(player_x, player_y)`가 마우스 커서 위치를 향해 일정 속도로 따라가도록 구현. 망치 공격은 DE2 보드 `KEY` 버튼과 마우스 좌클릭 모두 지원.

### 4.2. 그래픽 및 메모리(ROM/RAM) 최적화

1. **도트 스프라이트(Sprite) 기반 렌더링**
   * 640x480 전체 화면 프레임버퍼를 두는 대신, 실시간 픽셀 좌표 `(pixel_x, pixel_y)`와 오브젝트 좌표를 비교하는 **Sprite Generator 방식**을 사용한다.
   * 사람, 두더류, 몰드류(이동 모션, 채굴 모션, 피격 모션), 코인 더미, 배경 타일을 `16x16` 또는 `32x32` 크기의 컬러 인덱스 도트 배열(VHDL Constant ROM 테이블 또는 M4K Block ROM)로 저장하면 FPGA 메모리를 매우 적게 사용하면서도 깔끔한 도트 그래픽을 구현할 수 있다.

2. **반투명 원형 사거리 표시**
   * 현재 렌더링 중인 픽셀 `(x, y)`와 사람 중심 좌표 `(px, py)`의 거리 제곱을 계산:
     $$(x - px)^2 + (y - py)^2 \le R^2$$
   * 원의 테두리($R^2 - \epsilon \le d^2 \le R^2$)는 밝은 색으로 그리고, 원 내부는 `(x + y) mod 2 = 0` 조건(디더링/체크 패턴)이나 비트 시프트 색상 혼합(Alpha Blending 근사)을 적용하면 하드웨어에서 **반투명 원 효과**를 아주 자연스럽게 구현할 수 있다.

### 4.3. 다중 두더지 제어 및 충돌 판정 최적화

1. **동시 등장 최대 두더지 수(Active Mole Slots) 설정**
   * 한 라운드 목표 처치 수는 **50마리**이지만, 화면에 동시에 50마리분의 하드웨어 레지스터와 거리 계산기를 두면 FPGA Logic Elements(LE) 소모가 급증한다.
   * 따라서 **화면에 동시에 존재할 수 있는 두더지 슬롯(Active Slots)을 8~12마리**로 설계한다.
   * 두더지가 사람에게 잡히면 해당 슬롯이 비워지고(`active = '0'`), 라운드 처치 카운터(`kill_count`)가 1 증가한다. 빈 슬롯에는 Player 2가 다시 새로운 두더지를 소환할 수 있도록 하여 **누적 50마리 처치**를 깔끔하게 구현한다.
   * **밸런스 요소 추가**: Player 2가 키패드를 무작정 연타해 한 번에 모든 슬롯을 채우지 못하도록 **소환 쿨타임(예: 1.0~1.5초)** 또는 **소환 코스트 게이지**를 두면 게임성이 크게 향상된다.

2. **가장 가까운 두더지 판별 로직 (Nearest Target Finder)**
   * 하드웨어에서 제곱근($\sqrt{}$) 연산은 불필요하므로, 각 활성 두더지 슬롯 `i`에 대해 사람과의 거리 제곱 $D_i = \Delta x_i^2 + \Delta y_i^2$ (또는 맨해튼 거리 $|\Delta x_i| + |\Delta y_i|$)를 계산한다.
   * $D_i \le R^2$(사거리 내부)을 만족하는 두더지들 중 최소 $D_i$를 가진 인덱스를 비교기 트리(Comparator Tree)로 찾아, KEY 버튼 입력 시 해당 인덱스의 두더지를 타격 처리한다.

3. **50 MMC 보상 링크 및 16자리 수령 코드 모니터 텍스트 출력 (VGA Text & Font ROM)**
   * 블록체인 테스트넷(Ethereum Sepolia)에 프로젝트 전용 ERC-20 밈코인(**`MMC`**)을 발행하고, Cloudflare Tunnel 기반 보상 수령 웹 서버(`https://ministers-ind-wait-expired.trycloudflare.com/r/1` ~ `/r/5`)를 연동한다.
   * QR 코드를 사용하지 않고, 5개의 보상 링크(`/r/1` ~ `/r/5`)와 16자리 16진수 수령 코드(`373AA3656CFDFCEC` 등)를 `16행 × 34열` 문자열 상수 테이블(`REWARD_OVERLAY_TEXT`)과 `5x7` ASCII 비트맵 폰트(`get_font_pixel`)로 VHDL `Constant ROM`에 내장한다.
   * 게임 상태가 종료(`game_state = 1` 또는 `2`)가 되면 VGA 픽셀 렌더러가 화면 중앙 오버레이 창에 각 글자를 2배(`12x16` 픽셀)로 확대 렌더링하여, 승자가 모니터에 출력된 링크와 수령 코드를 보고 웹페이지에 입력해 즉시 **50 MMC**를 수령할 수 있게 만든다.

## 7. [실습 가이드 1] 아두이노 4x4 키패드 모듈 ↔ DE2 보드 결선(Wiring) 완벽 가이드 (`project2_top_mole_game.vhd` 기준)

아두이노용 4x4 매트릭스 키패드(멤브레인 또는 택트 스위치 타입)는 내부에 전원이나 칩이 없는 **순수 수동 스위치 격자(Row 4줄 × Column 4줄 = 총 8핀)** 구조입니다. 이를 실제 작성된 VHDL 코드([project2_top_mole_game.vhd](../project2_top_mole_game.vhd#L84-L87) 및 [keypad_scanner.vhd](../keypad_scanner.vhd#L15-L16))와 **100% 일치하도록** DE2 보드의 확장 헤더(`GPIO_0`, **JP1**)에 연결하는 방법을 정리합니다.

> **[중요: 실제 VHDL 코드의 `GPIO_0` 핀 할당 확인 (`project2_top_mole_game.vhd` 85~87행)]**
> ```vhdl
> -- GPIO_0(3..0) drives Keypad Columns; GPIO_0(7..4) reads Keypad Rows
> GPIO_0(3 downto 0) <= kp_col_out;          -- 열(Column 0~3) 스캔 출력
> GPIO_0(7 downto 4) <= (others => 'Z');     -- 행(Row 0~3) 입력용 High-Z 설정
> kp_row_in          <= GPIO_0(7 downto 4);  -- 행(Row 0~3) 상태 읽기
> ```
> 즉, **`GPIO_0[3:0]`이 Column(열 출력)**이고, **`GPIO_0[7:4]`가 Row(행 입력)**입니다!

### 7.1. 왜 '외부 풀업(Pull-up) 저항'이나 'Quartus 내부 풀업 설정'이 필요한가?
* 키패드는 버튼을 누르지 않았을 때 전선이 공중에 떠 있는 **플로팅(Floating / High-Z)** 상태가 됩니다.
* 만약 아무런 조치 없이 DE2 GPIO 핀에 직결하면, 버튼을 누르지 않아도 주변 노이즈 때문에 `'0'`과 `'1'`이 마구 튀는 오작동(Ghost Key)이 발생합니다.
* **해결 방법 (2가지 중 택 1 — 방법 A 강력 권장)**:
  * **방법 A (가장 깔끔! 점퍼선 8가닥만 직결 + Quartus Weak Pull-Up 설정)**: 브레드보드나 외부 저항 없이 키패드 8핀을 DE2 `GPIO_0`에 **암-암(F-F) 점퍼선 8개로 바로 꽂고**, Quartus II의 `Assignment Editor`에서 Row 입력 핀 4개(**`GPIO_0[4]` ~ `GPIO_0[7]`**)에 **`Weak Pull-Up Resistor = On`** 옵션을 켜는 방법입니다. (Cyclone II FPGA 내부의 약 25kΩ 풀업 저항이 활성화됨)
  * **방법 B (브레드보드 + 외부 10kΩ 풀업 저항 4개 사용)**: 내부 풀업 설정을 깜빡할까 봐 걱정된다면, 브레드보드에 `10kΩ` 저항 4개를 꽂아 Row 4개 핀(`GPIO_0[4]~GPIO_0[7]`)을 DE2 보드의 `VCC33 (3.3V, JP1 29번 핀)`에 연결해 주는 하드웨어 방식입니다.

### 7.3. DE2 보드 `GPIO_0` (JP1 헤더) 핀 배치 및 1:1 결선표 (`project2_top_mole_game.vhd` 기준)

DE2 보드 오른쪽에 있는 40핀 헤더 2개 중 **안쪽(왼쪽) 헤더가 `GPIO_0` (`JP1`)**입니다.  
> **주의**: `JP1` 헤더의 **11번 핀은 `+5V`**, **12번 핀은 `GND`**, **29번 핀은 `+3.3V(VCC33)`**, **30번 핀은 `GND`**입니다. 절대 출력 핀을 전원 핀에 잘못 꽂지 않도록 **가장 위쪽의 1번~8번 핀(`GPIO_0[0]` ~ `GPIO_0[7]`)**만 사용합니다!

```text
            [ DE2 보드 JP1 (GPIO_0) 40핀 헤더 상단부 ]
                 (보드 위쪽 / VGA 포트 방향)
```

### 7.4. Quartus II에서 내부 풀업 저항(`Weak Pull-Up`) 켜는 3단계 절차

외부 저항 없이 **암-암 점퍼선 8가닥만 깔끔하게 직결**하려면 Quartus II에서 Row 입력 핀인 **`GPIO_0[4]` ~ `GPIO_0[7]`**에 아래 설정만 해주면 됩니다.

1. Quartus II 상단 메뉴에서 **`Assignments` ➔ `Assignment Editor`**를 엽니다.
2. 표의 빈 줄에 아래 4개 행 입력 핀(`GPIO_0[4]`~`GPIO_0[7]`)을 추가하고 옵션을 설정합니다:
   * **To**: `GPIO_0[4]` ➔ **Assignment Name**: `Weak Pull-Up Resistor` ➔ **Value**: `On`
   * **To**: `GPIO_0[5]` ➔ **Assignment Name**: `Weak Pull-Up Resistor` ➔ **Value**: `On`
   * **To**: `GPIO_0[6]` ➔ **Assignment Name**: `Weak Pull-Up Resistor` ➔ **Value**: `On`
   * **To**: `GPIO_0[7]` ➔ **Assignment Name**: `Weak Pull-Up Resistor` ➔ **Value**: `On`
3. 또는 프로젝트의 `.qsf` 설정 파일에 아래 4줄을 직접 붙여넣어도 동일하게 작동합니다:
   ```tcl
   set_instance_assignment -name WEAK_PULL_UP_RESISTOR ON -to GPIO_0[4]
   set_instance_assignment -name WEAK_PULL_UP_RESISTOR ON -to GPIO_0[5]
   set_instance_assignment -name WEAK_PULL_UP_RESISTOR ON -to GPIO_0[6]
   set_instance_assignment -name WEAK_PULL_UP_RESISTOR ON -to GPIO_0[7]
   ```

> **동작 원리 요약 ([keypad_scanner.vhd](../keypad_scanner.vhd#L37-L128) Active-Low Matrix Scanning)**:
> * 평소에 `GPIO_0[7:4]`(`keypad_row`) 입력은 내부 풀업 저항 덕분에 모두 `"1111"` (High, 3.3V)을 유지합니다.
> * `keypad_scanner.vhd`가 1ms(50,000클럭)마다 `GPIO_0[3:0]`(`keypad_col`)에 `"1110"` ➔ `"1101"` ➔ `"1011"` ➔ `"0111"` 순서로 한 열씩만 `'0'`(GND)을 내보냅니다.
> * 4개 열을 모두 스캔한 시점(4ms 주기, `col_idx = 3`)에 `key_state(0..15)`를 검사하여 새로 눌린 상승 에지(`any_key = '1' and prev_any_key = '0'`)에서 딱 1클럭 동안 `spawn_pulse = '1'`을 발생시켜 두더지 1마리를 소환합니다!
