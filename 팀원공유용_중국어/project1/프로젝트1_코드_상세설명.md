## 1. VHDL 入门核心基础语法完全指南（必读！）

像 C 语言或 Python 这样的通用编程语言，是由 CPU **从上到下逐行顺序执行**的。而 **VHDL (VHSIC Hardware Description Language)** 不是软件，而是**用文字来设计实际数字电子电路（导线、逻辑门、多路选择器、触发器）的硬件描述语言**。在阅读代码之前，先理解以下 8 个核心语法规则，就能一眼看懂所有代码！

---

### 1.1 基本骨架：`library` / `entity`（芯片外壳） / `architecture`（芯片内部电路）
所有 VHDL 文件大致分为 3 个部分：

1. **`library` 与 `use`（引入工具箱）**：
   - 相当于 C 语言的 `#include <stdio.h>` 或 Python 的 `import`。
   - `library ieee;` ：声明使用国际电气和电子工程师协会 (IEEE) 标准库。
   - `use ieee.std_logic_1164.all;` ：导入定义了数字信号（`'0'`、`'1'`、`'Z'` 等）的必备程序包中的全部内容 (`.all`)。
   - `use ieee.numeric_std.all;` ：导入提供二进制加法、减法、大小比较、整数转换（`unsigned`、`signed`、`to_integer`、`to_unsigned` 等）的标准数学程序包。
   - `use work.seg7_pkg.all;` ：导入我们自己在当前工作库 (`work`) 中编写的 `seg7_pkg` 程序包。

2. **`entity`（黑盒芯片的外部引脚定义）**：
   - 定义伸出芯片外部的**输入/输出引脚 (Port)** 是什么，不写内部逻辑动作。
   ```vhdl
   entity 模块名称 is
       port (
           信号名称1 : in  数据类型;  -- in  : 从外部进入芯片内部的输入引脚
           信号名称2 : out 数据类型   -- out : 从芯片内部通向外部的输出引脚（最后一行末尾没有分号 ';'！）
       );
   end entity 模块名称;
   ```
   > **[语法注意事项]** 在 `port ( ... );` 内部的最后一行末尾如果加上分号 (`;`) 会报语法错误！只能在右括号 `);` 外侧写分号。

3. **`architecture`（芯片内部的实际电路设计图）**：
   - 设计在 `entity` 中定义的输入/输出引脚如何在内部连接和运算。
   ```vhdl
   architecture 设计方式名称 of 模块名称 is
       -- [声明部分] 声明仅在芯片内部使用的导线 (signal)、常量 (constant)、类型 (type) 等
   begin
       -- [正文部分] 编写实际电路行为（逻辑表达式、子模块连接、process 等）
   end architecture 设计方式名称;
   ```

### 1.2 VHDL 的 5 大核心数据类型 (Data Types) 与引号规则

VHDL 是一门类型（数据类型）检查非常严格的语言。

| 数据类型名称 | 含义与硬件结构 | 值的表示方法（引号规则） | 主要用途 |
| :--- | :--- | :--- | :--- |
| **`std_logic`** | **1 根导线（1 位）**<br/>（可表示 `'0'`、`'1'`、`'Z'`（高阻态/断开）、`'X'`（冲突）等 9 种电气状态） | **单引号 `' '`**<br/>例：`'0'`、`'1'` | 1 位时钟 (`CLOCK_50`)、单个开关 (`SW(0)`) |
| **`std_logic_vector`** | **多根导线捆绑在一起的总线 (Bus)**<br/>（只是单纯的位集合，**本身不能直接进行 `+`、`-` 算术运算！**） | **双引号 `" "`**<br/>例：`"1010"`、`"1111111"` | 多位输入/输出引脚 (`SW`、`KEY`、`HEX0~7`、`LEDR`) |
| **`unsigned`** | **无符号二进制数数组（仅表示 0 和正数）**<br/>（与 `std_logic_vector` 一样也是导线束，但**可以进行 `+ 1` 等算术运算！**） | **双引号 `" "`** | 时钟计数器 (`blink_cnt`)、将开关二进制值转换为数字时 |
| **`integer`** | **整数（负数、0、正数）**<br/>（通过像 `range -999 to 9999` 这样指定范围，来适配综合后的位数） | **不加引号，直接写数字**<br/>例：`0`、`777`、`-15` | 计数值 (`count_val`)、四则运算 (`+`、`-`、`*`、`/`、`mod`) |
| **`boolean`** | **真/假逻辑类型** | **`true` 或 `false`** | 条件判断标志 (`is_neg`、`div_zero`) |

#### 为什么像 `(6 downto 0)` 这样使用 `downto`？（`downto` vs `to`）
- **`std_logic_vector(6 downto 0)`**：表示从第 6 位（最左侧，最高有效位 MSB）到第 0 位（最右侧，最低有效位 LSB）共 **7 根导线**。
  - 就像我们写数字时左边是高位（千位）、右边是低位（个位）一样，在数字电路中也为了让左边位代表 $2^6$、右边位代表 $2^0$，而声明为 **`(大编号 downto 小编号)`**。
- **`array (0 to 21)`**：相反，给表格（数组）编排目录编号时，从第 0 行到第 21 行从上到下顺序递增更自然，因此使用 **`(小编号 to 大编号)`**。

### 1.3 数据类型转换 (Type Conversion) 三步公式完全理解

前面提到 `std_logic_vector` 只是单纯的导线束，不能直接做算术计算或整数转换。因此，在 `std_logic_vector` ↔ `integer` 之间转换时，必须经过桥梁类型 **`unsigned`**（使用 `use ieee.numeric_std.all;` 程序包中的函数）。

```text
   [导线束]                         [二进制数字]                          [十进制整数]
std_logic_vector  ──────►          unsigned          ──────►           integer
  "1000" (SW输入)   unsigned(...)  "1000" (二进制 8)   to_integer(...)      8

std_logic_vector  ◄──────          unsigned          ◄──────           integer
  "00001000"     std_logic_vector() "00001000"       to_unsigned(值, 位数)   8
```

1. **将开关输入 (`std_logic_vector`) 转换为可计算的整数 (`integer`) 时**：
   - 代码：`num_a := to_integer(unsigned(op_a_sw));`
   - 解释：① 用 `unsigned(op_a_sw)` 将 4 根导线束解释为“无符号二进制数” → ② 外层套用 `to_integer(...)` 转换为整数（`0`~`15`）。
2. **将计算得到的整数 (`integer`) 输出到 LED 引脚 (`std_logic_vector`) 时**：
   - 代码：`LEDR(7 downto 0) <= std_logic_vector(to_unsigned(abs_val, 8));`
   - 解释：① 用 `to_unsigned(abs_val, 8)` 将整数 `abs_val` 转换为 **8 位长度**的无符号二进制数 → ② 外层套用 `std_logic_vector(...)` 连接到实际的 LED 引脚导线束。

### 1.4 3 种箭头符号（`<=`、`:=`、`=>`）完全区分法

这是初学 VHDL 时最容易混淆的三个符号：

| 符号 | 名称 | 何时使用？ | 代码示例与直观解释 |
| :---: | :--- | :--- | :--- |
| **`<=`** | **信号 (Signal) 赋值运算符** | 向实际导线 (`signal`) 或输出端口 (`out`) 传输值时使用<br/>*（注意：仅在 `if val <= 21 then` 这样的条件表达式中才表示“小于等于”）* | `HEX0 <= seg7(0);`<br/>→ “将 `seg7(0)` 的结果连接到 `HEX0` 导线上！” |
| **`:=`** | **变量 (Variable) 赋值及初始值运算符** | ① 在 `process` 内部向临时计算用的变量 (`variable`) 立即写入值时<br/>② 在声明部分赋予初始默认值 (Default) 时 | `mult := 5;`<br/>→ “立即将 `5` 写入变量 `mult`！”<br/>`signal count_val : integer := 0;`<br/>→ “启动时将初始值设为 `0`！” |
| **`=>`** | **连接（映射）运算符** | ① 在 `case` 语句中表示“当满足此条件时执行该项”<br/>② 在 `(others => '0')` 中表示“将其余所有位填充为 `'0'`”<br/>③ 在 `port map` 中表示“将子模块的引脚与顶层模块的导线相连” | `when "00" => calc_result := num_a + num_b;`<br/>`LEDR <= (others => '0');`<br/>`CLOCK_50 => CLOCK_50` |

---

### 1.5 `Signal`（信号）vs `Variable`（变量）—— 为什么要同时使用两者？

- **`signal`（信号 = 实际的硬件导线或触发器寄存器）**：
  - 在 `architecture` 的声明部分创建，使用 **`<=`** 赋值。
  - **最重要的特点**：在 `process` 内部通过 `<=` 给 `signal` 赋值时，**该行并不会立即改变值，而是在 `process` 结束的瞬间（或时钟上升沿结束的瞬间）统一更新所有预约的值！**
- **`variable`（变量 = 仅在 `process` 内部使用的临时计算草稿纸）**：
  - 只能在 `process` 内部的声明部分声明，使用 **`:=`** 赋值。
  - 像 C 语言变量一样，**执行到该行的瞬间值就会立即改变！**
  - 例：用 `num_a := to_integer(unsigned(op_a_sw));` 将开关值写入 `num_a` 后，紧接着在下一行 `if num_a > 9 then num_a := 9;` 就能立即检查并修改刚刚写入的 `num_a` 值，原因正是因为它是 `variable`。（如果使用的是 `signal`，下一行读到的将还是旧值，从而导致严重错误！）

---

### 1.6 并发执行语句 (Concurrent) vs 顺序执行语句 (`process`)

1. **`process` 外部（`architecture` 正文）= 所有行同时工作！**：
   - 写在 `process` 外部的代码是用导线焊死在一起的独立硬件模块。无论代码行的上下顺序如何，**只要通电，所有行 24 小时同时工作**。
2. **`process(敏感列表)` 内部 = 像 C 语言一样从上到下按顺序解析！**：
   - 要使用复杂的条件语句（`if-elsif-else`、`case-when`），就必须打开 `process(...)` 块。
   - 括号内的信号（**敏感列表，Sensitivity List**）中只要有任意一个值发生变化，`process` 就会被唤醒，从 `begin` 到 `end process;` 自上而下执行代码以决定输出信号的值。
   - 如果在同一个 `process` 内先在上面给同一个信号（如 `HEX1`）赋值 `HEX1 <= seg7(16);`，又在下面的 `if` 语句中再次赋值 `HEX1 <= seg7(5);`，则**最后一次执行的值 (`seg7(5)`) 会最终输出到导线上**。

---

### 1.7 非常常用的便捷语法：`(others => '0')` 与运算符（`mod`、`/`、`abs`）

1. **`(others => '0')`（批量填充其余位）**：
   - 为了熄灭 18 位的 `LEDR`，如果自己数着 18 个零写成 `LEDR <= "000000000000000000";`，非常容易写错。
   - 这时只要写 `LEDR <= (others => '0');`，无论位宽是多少位，都表示**“将所有位都填充为 `'0'`”**。
2. **除法商 (`/`)、取余 (`mod`) 与绝对值 (`abs`)**：
   - 整数 (`integer`) 之间做 `/` 运算，会得到舍去小数部分的**商 (Quotient)**（例：`7 / 2` = `3`）。
   - 做 `mod` 运算，会得到相除后的**余数 (Remainder)**（例：`7 mod 2` = `1`）。
   - `abs(x)` 会在 `x` 为负数时去掉负号，返回其**绝对值 (Absolute value)**（例：`abs(-15)` = `15`）。

## 3. 整体系统架构与硬件输入/输出 (I/O) 引脚映射

### 3.1 整体系统框图

```text
[seg7_pkg.vhd] 通用 7-Segment 译码器程序包（内置基于 case 语句的 seg7() 函数）
   │  (use work.seg7_pkg.all)
   ├──▶ [U_COUNTER] counter_unit.vhd
   │      • 输入: CLOCK_50, KEY(3:0), SW(1), enable(~SW(0))
   │      • 功能: 2级同步/下降沿检测, 倍率(mult)增减, -999~9999 限幅(Clamping), 777 彩蛋(Jackpot)
   │      • 输出: cnt_HEX0..7, cnt_LEDR, cnt_LEDG
   │               │
   └──▶ [U_CALCULATOR] calculator_unit.vhd
          • 输入: SW(17:14) A, SW(13:10) B, SW(2:1) 运算符, SW(3) 进制
          • 功能: 0~9 输入限幅, 四则运算(+, -, *, /), 商/余数, 除以 0 报 Err
          • 输出: calc_HEX0..7, calc_LEDR, calc_LEDG
                   │
                   ▼
        [2-to-1 输出多路选择器(MUX)] ◄── 模式选择: SW(0)
          • SW(0) = '0' : 将计数器输出(cnt_*)传至实际引脚
          • SW(0) = '1' : 将计算器输出(calc_*)传至实际引脚
                   │
                   ▼
        [DE2 开发板物理输出引脚（或传至集成顶层 de2_unified_top）]
          HEX0~HEX7, LEDR(17:0), LEDG(7:0)
```

### 3.2 输入与输出端口完整映射表

| 端口名 | 位宽 | 计数器模式 (`SW(0) = '0'`) | 计算器模式 (`SW(0) = '1'`) | 电气特性与详细说明 |
| :--- | :---: | :--- | :--- | :--- |
| **`CLOCK_50`** | 1 bit | **50MHz 系统时钟**（用于边沿检测及 777 彩蛋闪烁） | 不使用 | 周期 `T = 20 ns` (`1 / 50,000,000 Hz`, `PIN_N2`) |
| **`SW(0)`** | 1 bit | **`'0'` : 选择计数器模式** | **`'1'` : 选择计算器模式** | 控制输出 MUX 及计数器 `enable` (`PIN_N25`) |
| **`SW(1)`** | 1 bit | **增减步长切换** (`'0'`: `+1/+2/-1`, `'1'`: `+5/+10/-5`) | **运算符选择低位 `op_sel(0)`** | 两种模式各自复用物理开关 `SW(1)` |
| **`SW(2)`** | 1 bit | 不使用 | **运算符选择高位 `op_sel(1)`** | `SW(2 downto 1)`: `"00"`=`+`, `"01"`=`-`, `"10"`=`*`, `"11"`=`/` |
| **`SW(3)`** | 1 bit | 不使用 | **输出进制选择 [附加功能]** (`'0'`: 十进制, `'1'`: 十六进制) | 切换 `+`、`-`、`*` 结果的显示进制 |
| **`SW(4)`** | 1 bit | *（集成模式下）* `'0'` = 运行 Project 1 | *（集成模式下）* `'1'` = 切换至 Project 2（打地鼠游戏） | Project 1 内部未使用的空闲开关 |
| **`SW(13 downto 10)`** | 4 bits | 不使用 | **操作数 B（`0`~`9`，10 及以上固定为 `9`）** | `SW(13)` 为 MSB ($2^3$)，`SW(10)` 为 LSB ($2^0$) |
| **`SW(17 downto 14)`** | 4 bits | 不使用 | **操作数 A（`0`~`9`，10 及以上固定为 `9`）** | `SW(17)` 为 MSB ($2^3$)，`SW(14)` 为 LSB ($2^0$) |
| **`KEY(3)` ~ `KEY(0)`** | 4 bits | `KEY(3)`: `+1/+5`, `KEY(2)`: `+2/+10`,<br/>`KEY(1)`: `-1/-5`, `KEY(0)`: **清 `0` 复位** | 不使用 | **Active-Low（低电平有效）**：常态为 `'1'`，按下为 `'0'` |
| **`HEX7` ~ `HEX4`** | 各 7 bits | 常态熄灭，**达到 `777` 时闪烁显示 `"JP77"`** | `HEX6`: 操作数 A, `HEX4`: 操作数 B | **Active-Low（低电平有效）**：`'0'`=点亮，`'1'`=熄灭 |

## 4. 文件 1：[seg7_pkg.vhd](./seg7_pkg.vhd)（程序包、函数、`case` 语句译码器语法及逐行完全解析）

### 4.1 7-Segment 数码管的硬件结构与 Active-Low 原理
FPGA 开发板上的 7-Segment 由 7 段条形 LED（`a`~`g`）组成，采用**给 `'0'` 点亮、给 `'1'` 熄灭的 Active-Low（共阳极，Common Anode）**方式。

```text
       aaa          位索引映射: std_logic_vector(6 downto 0)
      f   b         bit 6 = g (中间横杠)    bit 2 = c (右下竖杠)
      f   b         bit 5 = f (左上竖杠)    bit 1 = b (右上竖杠)
       ggg          bit 4 = e (左下竖杠)    bit 0 = a (顶部横杠)
      e   c         bit 3 = d (底部横杠)
      e   c
       ddd          ==> 按 "g f e d c b a" 顺序构成 7 位字符串 ('0'=ON, '1'=OFF)
```
例如，要显示数字 **`0`**，只需熄灭中间横杠 `g` (bit 6)（设为 `'1'`），并点亮其余 `f, e, d, c, b, a` (bit 5~0)（设为 `'0'`），因此结果为 **`"1000000"`**。

### 5.2 第一个进程：时钟同步边沿检测与加减运算语法解析 (Lines 25~56)

```vhdl

#### [逐行语法完全剖析 (Lines 25~56)]
- **Lines 26~29 (`process(CLOCK_50)`, `variable step, mult : integer;`, `begin`)**：
  - 仅敏感于 `CLOCK_50` 变化的同步时序进程。
  - `step`（当前时钟周期的增减量）和 `mult`（倍率 1 或 5）必须在赋值后立即用于下方的计算式 (`count_val + step`)，因此将其声明为 **`variable` (`:=`)** 而非 `signal`。
- **Line 30 (`if rising_edge(CLOCK_50) then`) —— 生成时序电路（D 触发器）**：
  - 每隔 20ns 当时钟从 `'0'`→`'1'` 上升时执行一次内部语句。在此块内通过 `<=` 被赋值的信号（`blink_cnt`、`key_sync0`、`key_sync1`、`count_val`）都会被综合为触发器寄存器。
- **Line 31 (`blink_cnt <= blink_cnt + 1;`)**：
  - 与模式 (`enable`) 无关、每个时钟都加 1 的 25 位自由运行 (Free-running) 计数器。
- **Lines 32~35 (`key_sync0 <= KEY; key_sync1 <= key_sync0;`)**：
  - `signal` (`<=`) 在时钟上升沿会**同时读取旧值并预约更新**，从而构成 2 级移位寄存器：`key_sync0` 存入刚采样的 `KEY`，`key_sync1` 存入 1 个时钟前的 `KEY` 状态。

#### 从时序表看 `key_sync0` 与 `key_sync1` 的下降沿检测原理
假设在时钟 `T2` 时刻用手指按下按键 `KEY(3)`：

| 时钟周期 | 物理按键 `KEY(3)` | `key_sync0(3)`（当前采样） | `key_sync1(3)`（1 时钟前采样） | 边沿检测条件<br/>`key_sync1='1' and key_sync0='0'` | 计数器动作 |

77:             LEDG <= (others => blink_cnt(23));
78:             -- 위에 프로세스에서 1씩 증가하므로 무조건 2의 23승 클럭마다 뒤집힘
79:             if blink_cnt(23) = '1' then
80:                 LEDR <= (others => '1');
81:                 HEX7 <= seg7(20); HEX6 <= seg7(21); HEX5 <= seg7(7); HEX4 <= seg7(7); -- "JP77"
82:             end if;
83:         end if;
84: 
85:         -- 4-Digit Decimal Display on HEX3..HEX0
86:         HEX0 <= seg7(abs_val mod 10);
87:         if abs_val >= 10      then HEX1 <= seg7((abs_val / 10) mod 10);   end if;
88:         if abs_val >= 100     then HEX2 <= seg7((abs_val / 100) mod 10);  end if;
89:         if is_neg             then HEX3 <= seg7(17);
90:         elsif abs_val >= 1000 then HEX3 <= seg7((abs_val / 1000) mod 10); end if;
91:     end process;
92: 
93: end architecture behavioral;
```

#### [逐行语法完全剖析 (Lines 58~93)]
- **Lines 59~62 (`process(count_val, blink_cnt)` 与变量声明)**：
  - 不依赖时钟，只要 `count_val` 或 `blink_cnt` 变化就立即重新计算画面输出的**组合逻辑进程**。
  - `is_neg` (`boolean`)：保存是否为负数。`abs_val` (`integer range 0 to 9999`)：保存绝对值。
- **Lines 63~66（默认值初始化 —— 防止生成意外锁存器 Latch）**：
  - 在组合逻辑进程最开头，先将 `HEX7~0` 全部初始化为空白 (`seg7(16)`)，将 `LEDR`/`LEDG` 全部初始化为 `'0'`。只有这样做，才能防止在下方的 `if` 语句中未被选中的数位变成记忆旧值的锁存器 (Latch)。
- **Lines 68~69 (`is_neg := (count_val < 0); abs_val := abs(count_val);`)**：
  - 将关系式 (`count_val < 0`) 的真/假结果直接存入 `is_neg`，并用 VHDL 内置函数 `abs()` 去掉负号后将大小存入 `abs_val`。
- **Lines 72~73 (`LEDR(13 downto 0) <= std_logic_vector(to_unsigned(abs_val, 14));`)**：
  - 将绝对值（`0`~`9999`，完全落在 $2^{14}-1 = 16383$ 以内）转换为 14 位二进制数并显示在 `LEDR(13:0)` 上；当为负数 (`is_neg = true`) 时，点亮最左侧的 `LEDR(17)` 以表示负号。
- **Lines 76~83（777 彩蛋闪烁周期计算）**：
  - `CLOCK_50` 的周期为 $T_{clk} = \frac{1}{50,000,000\text{ Hz}} = 20\text{ ns}$。
  - `blink_cnt` 虽然是 25 位 (`24 downto 0`) 计数器，但这里只单独取出其中的**第 23 位 (`blink_cnt(23)`)**。在二进制计数器中，无论总位宽是多少，第 $k$ 位总是每 $2^k$ 个时钟翻转一次，因此 `blink_cnt(23)` 每 $2^{23} = 8,388,608$ 个时钟就在 `'0'` 和 `'1'` 之间翻转一次：
    $$T_{half} = 8,388,608 \times 20\text{ ns} \approx 0.1677\text{ 秒}$$
  - 也就是说，约以 **0.33 秒的周期（每秒 3 次）**闪烁显示全部 8 个 `LEDG`、全部 18 个 `LEDR` 以及左侧 4 位 7-Segment (`HEX7~4`) 上的 **`"JP77"`** 字样。
- **Lines 86~90（4 位十进制数位提取 & 前导零隐藏）**：
  - **Line 86 (`HEX0`)**：即使值为 `0`，个位 $N \bmod 10$ 也始终显示。
  - **Line 87 (`HEX1`)**：仅当 `abs_val >= 10` 时才显示十位 $\lfloor N / 10 \rfloor \bmod 10$（小于 10 时保持第 64 行的空白）。
  - **Line 88 (`HEX2`)**：仅当 `abs_val >= 100` 时才显示百位 $\lfloor N / 100 \rfloor \bmod 10$。
  - **Lines 89~90 (`HEX3`)**：若为负数 (`is_neg`) 则优先显示 `'-'` (`seg7(17)`)，若为正数且 `abs_val >= 1000` 则显示千位 $\lfloor N / 1000 \rfloor \bmod 10$。
- **Lines 91~93 (`end process; end architecture behavioral;`)**：结束第二个进程与 `counter_unit` 结构体。

## 6. 文件 3：[calculator_unit.vhd](./calculator_unit.vhd)（类型转换、`case` 语句、四则运算语法及逐行完全解析）

本模块无需时钟，只要拨码开关输入发生变化，结果就会立即随之改变，是一个**纯组合逻辑电路 (Combinational ALU)**。

### 6.1 完整代码与逐行语法完全剖析（[calculator_unit.vhd](./calculator_unit.vhd)）

67:             HEX2 <= seg7(calc_result); HEX1 <= seg7(19); HEX0 <= seg7(calc_remainder);
68:             LEDR(3 downto 0) <= std_logic_vector(to_unsigned(calc_result, 4));
69:             LEDG(3 downto 0) <= std_logic_vector(to_unsigned(calc_remainder, 4));
70:         else
71:             -- Normal Arithmetic Result (+, -, *) in Decimal or Hexadecimal
72:             is_neg  := (calc_result < 0);
73:             abs_val := abs(calc_result);
74: 
75:             HEX0 <= seg7(abs_val mod base);
76:             if abs_val >= base then HEX1 <= seg7((abs_val / base) mod base);
77:             elsif is_neg       then HEX1 <= seg7(17);
78:             end if;
79: 
80:             LEDR(7 downto 0) <= std_logic_vector(to_unsigned(abs_val, 8));
81:         end if;
82:     end process;
83:

  - **Line 51 (`"00"`)**：加法 `num_a + num_b`（最大 `18`）。
  - **Line 52 (`"01"`)**：减法 `num_a - num_b`（`-9 ~ +9`）。

- **Lines 70~82 (`else` —— 普通运算 `+`、`-`、`*` 结果与动态负号位置)**：

## 7. 文件 4：[project1_top_countercalculator.vhd](./project1_top_countercalculator.vhd)（`port map` 模块连接与 `when-else` 语法及逐行完全解析）

#### [逐行语法完全剖析 (Lines 1~59)]
- **Lines 1~2 (`library ieee; use ieee.std_logic_1164.all;`)**：顶层模块只负责导线连接 (`port map`) 和 2:1 多路选择器切换，不直接执行算术运算，因此无需引入 `numeric_std`，仅引入 `std_logic_1164`。

  - 这是与 DE2 开发板物理引脚 (`CLOCK_50`, `SW(17:0)`, `KEY(3:0)`, `HEX0~7`, `LEDR(17:0)`, `LEDG(7:0)`) 一一对应的 Project 1 输入/输出接口。

  - 不同于在内部直接进行计算的 `behavioral`，负责组装子元件并连接布线的顶层模块按惯例使用 **`structural`（结构化设计）** 作为结构体名称。
- **Lines 17~24（内部连线 `signal` 声明与 `begin`）**：
  - `cnt_HEX0~7`、`cnt_LEDR`、`cnt_LEDG`：用于临时接收计数器模块 (`U_COUNTER`) 输出的内部导线。
  - `calc_HEX0~7`、`calc_LEDR`、`calc_LEDG`：用于临时接收计算器模块 (`U_CALCULATOR`) 输出的内部导线。

  - 使用 VHDL-93 直接实体实例化 (Direct Entity Instantiation) 语法，无需声明 `component` 即可直接调用 `counter_unit`。
  - 将 `CLOCK_50`、`counter_enable`、`SW(1)` (`step_mode`)、`KEY` 连接到输入端，并将输出端连接到 `cnt_*` 内部导线。
- **Lines 38~45 (`U_CALCULATOR : entity work.calculator_unit port map (...)`)**：
  - 将 `SW(17 downto 14)` → `op_a_sw`（操作数 A）、`SW(13 downto 10)` → `op_b_sw`（操作数 B）、`SW(2 downto 1)` → `op_sel`（运算符）、`SW(3)` → `base_sel`（十/十六进制）连接好，并将输出端连接到 `calc_*` 内部导线。
- **Lines 48~57 (`HEX0~7`、`LEDR`、`LEDG` 输出多路选择器)**：
  - 使用并发条件信号赋值语句 (`when SW(0) = '0' else`)，当 `SW(0) = '0'` 时将计数器输出 (`cnt_*`)、当 `SW(0) = '1'` 时将计算器输出 (`calc_*`) 发送到实际外部引脚。（在硬件上会综合为 10 个 2:1 多路选择器。）
  - **关键区分（`=>` vs `<=`）**：`port map` 中的 **`=>`** 并不表示数据流向，而是表示**“子模块端口（左） = 当前文件导线（右）”**的配对连接符号（`in` 端口为右→左输入，`out` 端口为左→右输出）。相反，第 48~57 行中的 **`<=`** 才是将右侧选出的值真正驱动输出到左侧外部引脚的赋值符号。
- **Line 59 (`end architecture structural;`)**：结束顶层结构体。

## 8. 进阶理论：Quartus 综合器 (Synthesizer) 将 VHDL 代码转换为实际硬件电路的原理

以下是教授或助教在问答环节（Level of Understanding 考核）中经常提问的 3 个核心硬件综合原理：

1. **为什么两个子模块 (`U_COUNTER`, `U_CALCULATOR`) 不直接连接到同一个 `HEX0~HEX7` 引脚，而是必须经过 MUX？**
   - 在硬件电路中，如果将两个不同模块的输出导线直接短接到同一个物理引脚上，当一端输出 `'1'` (3.3V) 而另一端输出 `'0'` (0V) 时，就会发生**信号冲突（总线争用 / 短路，Bus Contention / Short Circuit）**。
   - 因此，必须先用 `cnt_HEX*`、`calc_HEX*` 这样的独立内部导线分别接收各模块的输出，再通过顶层模块的 **2-to-1 多路选择器 (`when SW(0) = '0' else`)** 确保同一时刻只有一个模块的信号输出到物理引脚。
2. **`counter_unit` 中的 `abs_val / 10` 和 `abs_val mod 10` 在硬件上是如何实现的？**
   - FPGA 内部的 Cyclone II 逻辑单元 (LE) 会将针对常量 `10`、`100`、`1000` 的除法与取余综合为**组合逻辑除法/取余运算器 (Combinational Divider/Modulo Array)**，无需等待时钟周期，只要 `count_val` 一变化就会立即算出各个十进制数位（BCD 值）。
3. **与 Project 2 合并到同一块开发板 (`de2_unified_top.vhd`) 时，为什么对 Project 1 完全没有影响？**
   - Project 1 不使用 `SW(5 downto 4)`，因此 `de2_unified_top.vhd` 将 **`SW(4)`** 用作主切换开关（`SW(5)` 作为与 `SW(6)` 之间的防误触缓冲间隔）。当 `SW(4) = '0'` 时，`KEY`、`SW`、`HEX0~7`、`LEDR/G` 100% 连接到 Project 1；当 `SW(4) = '1'` 时，将输入给 Project 1 的 `KEY` 信号固定为 `"1111"`（未按下状态），从而在游玩 Project 2 游戏期间也能原封不动地保留 Project 1 的计数值。
