# Design Project #2: 打地鼠游戏（Crypto Miner Defense）策划与实现可行性分析

---

## 1. 项目概述

* **项目名称**：打地鼠游戏 - 加密防御（暂定名：*Digital Miner vs. Crypto Holder*）
* **游戏类型**：双人非对称 PvP 实时防御游戏
* **开发环境**：FPGA（DE2 开发板）、VHDL
* **外部输入/输出设备（已确定）**：
  * **画面输出**：DE2 VGA 接口 ➔ `VGA 转 HDMI 转换器` + `HDMI 线缆` ➔ 显示器（`640x480 @ 60Hz`）
  * **Player 1（人类操作）**：`NETmate PS/2 有线光电鼠标 (NM-OM01)`（直连 DE2 PS/2 接口，追踪鼠标光标位置移动）
  * **Player 1（锤子攻击）**：DE2 开发板按键（`KEY`）或鼠标左键点击
  * **Player 2（召唤地鼠）**：`Arduino 4x4 矩阵键盘模块`（直连 DE2 GPIO 引脚）

---

## 2. 世界观与故事背景

在未来社会，加密货币（Crypto Coin）像现实货币一样被广泛使用。  
**人类（Player 1）**经过长时间的辛苦挖矿，在地图中央积攒了一堆共 **100 枚硬币**。  
另一方面，**地鼠军团（Player 2 - 地鼠大队长）**也垂涎这些硬币并试图进行挖矿（Mining），但由于自身没有直接计算加密算法的技术，它们企图通过物理抢夺人类积攒好的硬币来“挖矿（Mining）”。  
人类必须守护中央的硬币堆不被这些地鼠（Digital Miner）夺走，而地鼠大队长则需要不断召唤地鼠，将 100 枚硬币全部挖空。

## 3. 游戏规则与详细系统

### 3.1. 画面美术与地图结构
* **美术风格**：采用像素风背景世界、人类角色（手持锤子）、宝可梦**螺钉地鼠（普通地鼠） / 龙头地鼠**像素精灵图。
* **地图布局**：
  * 在正方形地图的正中央放置**硬币堆（初始 100 枚硬币）**。
  * 以硬币堆为中心存在一定距离的**内部正方形（安全区边界）**，地鼠只能在该正方形**外侧区域**被召唤。

```
+---------------------------------------+
|  [1]     [2]     [3]     [A]          |  <- 与 4x4 键盘外圈 12 个按键对应的
|                                       |     外围可召唤区域
|  [4]   +-------------------+   [B]    |
|        |    禁止召唤区域    |          |
|        |                   |          |
|  [7]   |     [硬币堆]       |   [C]    |
|        |     (100枚)       |          |
|        +-------------------+          |
|  [*]     [0]     [#]     [D]          |
+---------------------------------------+
```

### 3.2. 角色定位与操作方式（双人非对称 PvP）

| 分类 | Player 1（人类 / 防守阵营） | Player 2（地鼠大队长 / 进攻阵营） |
| :--- | :--- | :--- |
| **目标** | 坚持到第 5 回合结束且保住至少 1 枚硬币（初始 100 枚） | 在 5 回合内将硬币堆（100 枚）全部挖空使其归零 |
| **移动方式** | 跟随 **PS/2 鼠标**光标位置进行 8 方向（或 360 度）追踪移动 | 被召唤的地鼠向中央硬币堆进行 **8 方向自动移动** |
| **动作操作** | 使用 **DE2 开发板 KEY 按键**（或**鼠标左键**）挥锤攻击 | 按下 **Arduino 4x4 矩阵键盘**在对应区域召唤地鼠 |
| **特殊规则** | 角色周围显示**半透明圆形攻击范围**，攻击范围内的**最近一只地鼠** | 键盘**外圈 12 个按键**用于在外围召唤普通地鼠，**内侧 4 个按键**可扩展用于召唤特殊地鼠（龙头地鼠等） |

### 3.3. 挖矿与战斗机制
* **地鼠挖矿（Mining）**：
  * 被召唤的地鼠会自动向中央硬币堆移动。
  * 接近硬币堆一定距离以内后，会执行 **1 秒钟的挖矿动作**，动作完成后**减少 1 枚硬币**。
* **人类攻击（Hammer Attack）**：
  * 人类角色周围显示透明的圆形攻击范围。
  * 靠近地鼠使其进入攻击范围圆内时，按下 DE2 开发板的 KEY 按键，即可攻击并消灭范围内**距离最近的 1 只地鼠**。

### 3.4. 回合与胜利条件
* **回合结束条件**：**第 1、2 回合各 20 秒**，**第 3 回合 30 秒**（或者消灭 50 只地鼠时提前结束），结束后进入下一回合。
* **总回合数**：共进行 **3 个回合**。
* **各回合难度（移速·生命值·龙头地鼠概率）及召唤·攻击·连击规则**：
  * **开局前 10 秒规则说明 & 3 秒倒计时**：游戏开始（复位）时，前 `10 秒` 内先显示规则说明画面（`10~4 秒`），随后在开战前 `3 秒`（`3·2·1`）倒计时结束后正式开始游戏。
  * **挥空惩罚**：若攻击范围（$R=48$）内没有地鼠却挥锤攻击，人类将**停顿 0.5 秒（30 帧）**且连击数**下降 1 级**（`LV3(9+) ➔ LV2(6) ➔ LV1(3) ➔ LV0(0)`）。
  * **连续击杀连击强化（`3 / 6 / 9` 连击，跨回合保留）**：
    * **3 连击以上（1 阶段）**：攻击伤害从 **`1` ➔ `2`** 提升
    * **6 连击以上（2 阶段）**：人类移动速度从 **`2 px/f` ➔ `3 px/f`** 提升
    * **9 连击以上（3 阶段）**：基础伤害为 `2`，有 **`4/8 (50%)` 概率触发暴击重击（伤害 `3`，无击退）**
  * **仅使用外圈 12 个按键进行召唤**：仅接收 4x4 键盘外圈 12 个按键的输入，中间 4 个按键（`5, 6, 8, 9`）不接收输入。
  * **各回合地鼠移速·生命值·龙头地鼠概率**：
    * **第 1 回合**：普通地鼠生命值 `1`（速度 `0.5 px/f`），龙头地鼠 **`1/8` 概率**出现 · 生命值 `2`（`1.0 px/f`）
    * **第 2 回合**：普通地鼠生命值 `2`（速度 `1.0 px/f`），龙头地鼠 **`2/8` 概率**出现 · 生命值 `4`（`1.5 px/f`）
    * **第 3 回合**：普通地鼠生命值 `3`（速度 `1.5 px/f`），龙头地鼠 **`4/8` 概率**出现 · 生命值 `6`（`2.0 px/f`）
  * **场上上限 8 只限制**：场上同时能存在的地鼠最多为 8 只（`MAX_MOLES = 8`）。
  * **禁止在同一位置连续召唤**：不能连续在紧邻上一次召唤过的区域（`last_spawn_zone`）再次召唤。
* **硬币累计制**：硬币（**初始 50 枚**）不会每回合重置，而是**在 3 个回合内全程累计（共享）**。
* **最终胜负与真实模因币（50 MMC）链接及领取码奖励**：
  * **地鼠（Player 2）获胜**：在第 3 回合结束前使中央硬币归 `0`，则立即获胜。
  * **人类（Player 1）获胜**：坚持到第 3 回合全部结束且中央仍剩余 `1` 枚及以上硬币，则获胜。
  * **胜者奖励链接与领取码显示器输出（不使用二维码 ➔ 采用文本直接输出方式）**：
    * 游戏结束时不生成二维码，而是使用 `5x7` 点阵字体（放大 2 倍为 `12x16` 像素）在 VGA 显示器画面中央的叠加层窗口中清晰输出 **50 MMC 奖励领取网页链接（`https://ministers-ind-wait-expired.trycloudflare.com/r/1` ~ `/r/5`）**与 5 组 **16 位十六进制领取码（Claim Code）**。

## 4. FPGA（DE2 开发板）可实现性与硬件设计分析

本策划**可通过 DE2 开发板与 VHDL 100% 实现**，其结构能够同时满足评审维度中的**创意性（Creativity）**、**完成度（Quality）**与**理解度（Level of understanding）**。不过需要结合硬件（FPGA）特性应用以下设计优化策略。

### 4.1. 外部模块硬件接口（已确定）

1. **VGA 显示器输出（`VGA 转 HDMI 转换器` + `HDMI 线缆`）**
   * 利用 DE2 开发板板载 VGA DAC，以 `640x480 @ 60Hz`（像素时钟 25MHz）分辨率输出模拟信号，经 `VGA 转 HDMI 转换器`输出至 HDMI 显示器。
   * 将画面划分为左侧正方形游戏地图（`480x480` 区域）与右侧状态 UI 区域（`160x480`）。

2. **Arduino 4x4 矩阵键盘模块（Player 2 - 直连 DE2 GPIO）**
   * 由于其本身为 4 行（Row）引脚与 4 列（Column）引脚（共 8 引脚）的数字矩阵结构，可直接连接至 DE2 开发板 `GPIO`。
   * 在 VHDL 内部以约 1kHz 频率驱动列扫描时钟，并对行输入进行消抖（Debouncing），从而精准识别 16 个按键（外圈 12 个 + 内侧 4 个）的输入。

3. **PS/2 有线光电鼠标（`NETmate NM-OM01`，Player 1 - 直连 DE2 PS/2 接口）**
   * 直接连接至 DE2 开发板板载 PS/2 接口（`PS2_CLK`、`PS2_DAT`），无需额外的 ADC 或 Arduino，硬件架构简洁干净。
   * VHDL 内部的 PS/2 双向控制器在初始化时发送 `0xF4`（Enable Data Reporting）命令，此后实时接收来自鼠标的 3 字节移动数据包（`按键状态`、`ΔX`、`ΔY`）。
   * 实时更新屏幕上的鼠标光标 `(cursor_x, cursor_y)` 坐标，并控制人类角色 `(player_x, player_y)` 以固定速度朝鼠标光标位置追踪移动。锤子攻击同时支持 DE2 开发板 `KEY` 按键与鼠标左键点击。

### 4.2. 图形与存储（ROM/RAM）优化

1. **基于像素精灵图（Sprite）的渲染**
   * 不设置 640x480 全屏帧缓冲区（Framebuffer），而是采用将实时像素坐标 `(pixel_x, pixel_y)` 与对象坐标进行比较的 **Sprite Generator（精灵生成器）方式**。
   * 将人类、普通地鼠、龙头地鼠（移动动作、挖矿动作、受击动作）、硬币堆、背景地砖存储为 `16x16` 或 `32x32` 大小的颜色索引点阵数组（VHDL Constant ROM 表或 M4K Block ROM），既能大幅节省 FPGA 存储资源，又能呈现清晰的像素画面。

2. **半透明圆形攻击范围显示**
   * 计算当前正在渲染的像素 `(x, y)` 与人类中心坐标 `(px, py)` 的距离平方：
     $$(x - px)^2 + (y - py)^2 \le R^2$$
   * 将圆的边框（$R^2 - \epsilon \le d^2 \le R^2$）绘制为亮色，圆内部则应用 `(x + y) mod 2 = 0` 条件（抖动混色/棋盘格图案）或移位混色（近似 Alpha Blending），即可在硬件上极其自然地实现**半透明圆效果**。

### 4.3. 多地鼠控制与碰撞判定优化

1. **最大同时出场数量（Active Mole Slots）设定**
   * 虽然单回合目标击杀数为 **50 只**，但如果在硬件中同时布置 50 只地鼠的寄存器与距离计算器，FPGA 逻辑单元（LE）消耗将急剧上升。
   * 因此，设计为**屏幕上同时存在的地鼠槽位（Active Slots）为 8~12 只**。
   * 地鼠被人类击杀后对应槽位清空（`active = '0'`），回合击杀计数器（`kill_count`）加 1。Player 2 可以在空槽位中继续召唤新地鼠，从而简洁地实现**累计击杀 50 只**的机制。
   * **补充平衡性要素**：为防止 Player 2 无脑连按键盘瞬间填满全部槽位，若加入**召唤冷却时间（例如 1.0~1.5 秒）**或**召唤能量条**，可大幅提升游戏可玩性。

2. **最近目标判定逻辑（Nearest Target Finder）**
   * 硬件中无需进行平方根（$\sqrt{}$）运算，只需为每个活跃地鼠槽位 `i` 计算与人类之间的距离平方 $D_i = \Delta x_i^2 + \Delta y_i^2$（或曼哈顿距离 $|\Delta x_i| + |\Delta y_i|$）。
   * 利用比较器树（Comparator Tree）在满足 $D_i \le R^2$（攻击范围内）的地鼠中找出 $D_i$ 最小的索引，按下 KEY 按键时对该索引对应的地鼠执行打击处理。

3. **50 MMC 奖励链接与 16 位领取码显示器文本输出（VGA Text & Font ROM）**
   * 在区块链测试网（Ethereum Sepolia）上发行项目专用的 ERC-20 模因币（**`MMC`**），并对接基于 Cloudflare Tunnel 的奖励领取 Web 服务器（`https://ministers-ind-wait-expired.trycloudflare.com/r/1` ~ `/r/5`）。
   * 不使用二维码，而是将 5 个奖励链接（`/r/1` ~ `/r/5`）与 16 位十六进制领取码（如 `7325DF893DE81A34` 等）以 `16 行 × 34 列` 字符串常量表（`REWARD_OVERLAY_TEXT`）及 `5x7` ASCII 点阵字体（`get_font_pixel`）的形式内置在 VHDL `Constant ROM` 中。
   * 当游戏状态进入结束（`game_state = 1` 或 `2`）时，VGA 像素渲染器在屏幕中央的叠加层窗口中将每个字符放大 2 倍（`12x16` 像素）进行渲染，使胜者能够看着显示器上输出的链接与领取码在网页中输入，立即领取 **50 MMC**。

## 7. [实操指南 1] Arduino 4x4 矩阵键盘模块 ↔ DE2 开发板接线（Wiring）完整指南（基于 `project2_top_mole_game.vhd`）

Arduino 4x4 矩阵键盘（薄膜式或轻触开关式）内部无电源和芯片，属于**纯无源开关矩阵（4 行 Row × 4 列 Column = 共 8 根引脚）**结构。下面整理将其与实际编写的 VHDL 代码（[project2_top_mole_game.vhd](../project2_top_mole_game.vhd#L84-L87) 与 [keypad_scanner.vhd](../keypad_scanner.vhd#L15-L16)）**100% 匹配**地接入 DE2 开发板扩展排针（`GPIO_0`，**JP1**）的方法。

> **[重要：核对实际 VHDL 代码中的 `GPIO_0` 引脚分配（`project2_top_mole_game.vhd` 第 85~87 行）]**
> ```vhdl
> -- GPIO_0(3..0) drives Keypad Columns; GPIO_0(7..4) reads Keypad Rows
> GPIO_0(3 downto 0) <= kp_col_out;          -- 열(Column 0~3) 스캔 출력
> GPIO_0(7 downto 4) <= (others => 'Z');     -- 행(Row 0~3) 입력용 High-Z 설정
> kp_row_in          <= GPIO_0(7 downto 4);  -- 행(Row 0~3) 상태 읽기
> ```
> 即 **`GPIO_0[3:0]` 为 Column（列输出）**，**`GPIO_0[7:4]` 为 Row（行输入）**！

### 7.1. 为什么需要“外部上拉（Pull-up）电阻”或“Quartus 内部上拉设置”？
* 未按下按键时，矩阵键盘的导线上处于悬空状态的**浮空（Floating / High-Z）**态。
* 如果不做任何处理直接连到 DE2 GPIO 引脚，即使不按键，周围噪声也会导致信号在 `'0'` 和 `'1'` 之间剧烈跳动，引发误触发（Ghost Key）。
* **解决方法（二选一 —— 强烈推荐方法 A）**：
  * **方法 A（最简洁！仅用 8 根杜邦线直连 + Quartus 开启 Weak Pull-Up）**：无需面包板或外部电阻，直接用 **8 根母对母（F-F）杜邦线**将键盘 8 引脚插到 DE2 `GPIO_0` 上，并在 Quartus II 的 `Assignment Editor` 中为 4 个行输入引脚（**`GPIO_0[4]` ~ `GPIO_0[7]`**）开启 **`Weak Pull-Up Resistor = On`** 选项。（将激活 Cyclone II FPGA 内部约 25kΩ 的上拉电阻）
  * **方法 B（面包板 + 4 个外部 10kΩ 上拉电阻）**：如果担心忘记设置内部上拉，可以在面包板上插 4 个 `10kΩ` 电阻，将 4 个 Row 引脚（`GPIO_0[4]~GPIO_0[7]`）上拉连接至 DE2 开发板的 `VCC33 (3.3V, JP1 第 29 号引脚)`。

### 7.4. 在 Quartus II 中开启内部上拉电阻（`Weak Pull-Up`）的 3 步流程

若要在不使用外部电阻的情况下**仅用 8 根母对母杜邦线整洁直连**，只需在 Quartus II 中对 Row 输入引脚 **`GPIO_0[4]` ~ `GPIO_0[7]`** 进行如下设置：

1. 在 Quartus II 顶部菜单栏打开 **`Assignments` ➔ `Assignment Editor`**。
2. 在表格空行中添加以下 4 个行输入引脚（`GPIO_0[4]`~`GPIO_0[7]`）并设置选项：
   * **To**: `GPIO_0[4]` ➔ **Assignment Name**: `Weak Pull-Up Resistor` ➔ **Value**: `On`
   * **To**: `GPIO_0[5]` ➔ **Assignment Name**: `Weak Pull-Up Resistor` ➔ **Value**: `On`
   * **To**: `GPIO_0[6]` ➔ **Assignment Name**: `Weak Pull-Up Resistor` ➔ **Value**: `On`
   * **To**: `GPIO_0[7]` ➔ **Assignment Name**: `Weak Pull-Up Resistor` ➔ **Value**: `On`
3. 或者直接将以下 4 行粘贴到项目的 `.qsf` 配置文件中，效果完全相同：
   ```tcl
   set_instance_assignment -name WEAK_PULL_UP_RESISTOR ON -to GPIO_0[4]
   set_instance_assignment -name WEAK_PULL_UP_RESISTOR ON -to GPIO_0[5]
   set_instance_assignment -name WEAK_PULL_UP_RESISTOR ON -to GPIO_0[6]
   set_instance_assignment -name WEAK_PULL_UP_RESISTOR ON -to GPIO_0[7]
   ```

> **工作原理概要（[keypad_scanner.vhd](../keypad_scanner.vhd#L37-L128) Active-Low Matrix Scanning）**：
> * 平时，得益于内部上拉电阻，`GPIO_0[7:4]`（`keypad_row`）输入全部保持为 `"1111"`（High, 3.3V）。
> * `keypad_scanner.vhd` 每隔 1ms（50,000 个时钟周期）按 `"1110"` ➔ `"1101"` ➔ `"1011"` ➔ `"0111"` 的顺序在 `GPIO_0[3:0]`（`keypad_col`）上轮流向其中一列输出 `'0'`（GND）。
> * 在完成全部 4 列扫描的时刻（4ms 周期，`col_idx = 3`），检查 `key_state(0..15)`，一旦检测到新按下的上升沿（`any_key = '1' and prev_any_key = '0'`），便产生持续恰好 1 个时钟周期的 `spawn_pulse = '1'`，召唤出 1 只地鼠！

### 8.3. `vga_renderer_unit.vhd` 的实际文本叠加层渲染电路
